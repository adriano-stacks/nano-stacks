## 2026-07-29T15:05:00Z

A signer replacement now holds: 211 consecutive canonical blocks across a reward
cycle rollover, every one carrying nano's signature, with transfers, a contract
deploy, contract calls, tenure changes, coinbases and sortitions all confirmed
by receipt. `hacknet/harness.sh` reproduces the whole run from a clone.

Five consensus or protocol defects had to be fixed to get there, each found by a
different oracle:

1. MARF: splitting a node's compressed path packs the new leaf into the *first*
   pointer slot and the displaced node into the second, the reverse of a split
   leaf. Random keys never collide deeply enough to reach that layout, so the
   lockstep script could not produce it; the new script searches for colliding
   keys. Found by `replay-divergence`, which descends into the child whose hash
   differs.
2. Matured miner rewards past the checkpoint window: derived from the tenures
   nano executes, including the burnchain coinbase accumulation and the
   recipient the coinbase transaction names. A missing payout now errors.
3. A tenure the checkpoint lands inside has fees only the checkpoint can
   measure, so replaying its tail must not add to them.
4. `MessageSlotID::StateMachineUpdate` is 2, the contract index, not 6, the
   payload type byte. Announcements were going to a lane nobody reads, and a
   stock signer will not validate any block without a majority view.
5. Signing is two phased: promise first, sign once the promises reach threshold
   weight. Without nano's promise the stock signers withheld their signatures.

Still open: nano refuses ~30s of re-proposals after signing a conflicting block
at the same height, which is noisy but does not stall the chain; and the miner
replacement is untouched.

Two more defects fixed to get the mining half working:

6. Epoch 4 fixed the header version at 1, which also puts the miner-flagged
   transaction list in the hash preimages. Blocks built at version 0 were
   rejected outright.
7. Mining was a one-shot tool re-run from a shell loop, and each run replayed
   the chain from the checkpoint before it could check for a win. Every proposal
   therefore arrived against a tenure the signers had already left behind and
   was rejected as a sortition view mismatch. Committing, following and mining
   now share one process that keeps its executed state across burn blocks.

Still open: nano mines only the first block of each tenure, so the transactions
that arrive during its tenures wait for the next miner; a tenure extend is not
implemented either. Both are mempool work, not consensus work.
