The guard is not optional. During an import, journalling is off, so a partial trie
cannot be resumed and the whole import must be redone from a removed chainstate —
a filesystem that fills mid-import costs hours, and this filesystem is shared with
Bitcoin Core.

## Rollback procedure

1. Stop the node with `SIGTERM` and wait for it to exit; it honours the signal in
   about five seconds and seals nothing partially.
2. Start the previous artifact against the **same** state directory. A state may be
   continued by any binary whose compiler identity and profile fingerprint match
   the ones its `checkpoint-provenance.toml` and `consensus_profile` row record;
   the node checks this itself and refuses otherwise, so a wrong rollback target
   fails closed rather than executing.
3. If the rollback target has a *different* compiler identity, the state cannot be
   continued and must be re-imported from the attested bundle. There is no
   supported repin; `adopt-imported-state` applies only to a pristine import that
   has executed nothing past its checkpoint, and refuses anything else.
4. A derived sortition chain is re-seeded automatically where it is invalidated, so
   no manual sortition surgery is part of any rollback.
